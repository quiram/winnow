# Task tracking

Work on winnow is tracked as **GitHub Issues on [quiram/winnow](https://github.com/quiram/winnow/issues)**.

## Reaching it

Use whatever access to GitHub the current environment offers — the `gh` CLI, a GitHub MCP server, or the REST API with a token. They are equivalent for reading and writing issues, so there is no preference to state; pick what is available and working. If more than one is available, either will do.

The only rule is to confirm access before relying on it, and to probe read-only: list or read an existing issue, never create a test one.

## Ticket conventions

None recorded yet, so `create-tasks`' own defaults apply: lead with the business goal, dedupe against existing issues, one goal per ticket, and keep tickets independent where possible, using GitHub's native dependency links where a dependency is unavoidable.
